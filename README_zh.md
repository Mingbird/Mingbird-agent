# 🐦 蜂鸟 · 本地 AI 助手

**一个跑在普通笔记本上的本地 AI agent——不挑显卡,不用云。**

[English](README.md) · Apache-2.0 · Windows 10/11

![preview](https://raw.githubusercontent.com/Gustor-Wang/hummingbird-agent/main/assets/preview-en.png)


主流 agent 框架几乎都默认"你有云 API 或大显存"。蜂鸟正好相反:**为小模型(0.5–9B MoE)和核显机器优化,全离线、能干真活**。我们在一台只有 AMD Radeon 680M 核显、16GB 系统内存(无独显)的笔记本上实际开发、实测了 39 轮基准(V1–V39)——在这样低的配置下,它依然几乎即时响应,速度接近直接与 Ollama 对话,无需额外等待。

## 我们要解决的问题

**1–4B 本地超小模型,在传统 agent 里根本无法运行。** 这是我们踩坑踩出来的:主流 agent 框架(为云端大模型设计)遇到 2B 模型就崩——全量工具 prefill 把上下文预算吃光、模型无法自修、原地打转死循环。而少数**专门为小模型优化**的 agent,我们实测后同样发现**没有可靠的长任务能力**:要么对着工具"表演"而不干活,要么在多步任务中悄悄死掉。

**我们的最主要贡献:1–4B 超小模型,也能可靠完成超长、复杂的任务。** 不是把小模型假装成大模型,而是造一个 harness 去补齐它们做不到的事——替它们跑测试并把精确失败(file:line)喂回去、改坏自动回滚(`.bak`)、用问答/任务分层掐死工具表演循环、按需只加载任务相关的工具(扁平 prefill,上下文 -50%+)。

这不是套壳。这是一个**围绕小模型能做/不能做什么而设计**的 agent harness,并用 **39 轮基准(V1–V39)** 验证——每一轮都是一次在小模型上端到端跑通的真任务。

## 为什么小模型值得一个真 agent

小模型诚实地暴露自己的短板——harness 替它补齐:

- **它不会自己 debug 自己的代码。** harness 亲自跑测试、解析精确失败位置(file:line),把可操作的报错喂回去;改坏了还有 `.bak` 自动回滚。
- **上下文金贵。** 工具按类别按需加载(文件 / 代码 / 网络 / 记忆 / MCP),而不是一次性全塞。prefill 上下文 -50%+,每次请求更快。
- **它会对着"你好"表演工具调用。** 问答/任务分层:闲聊就轻量回答、答完即停;真任务才解锁全套工具。
- **它会原地复读。** 重复工具调用、近似死循环会被拦截并强制收尾。

## 能干什么

- **全离线** — 数据绝不离开本机。无账号、无遥测、无云。
- **真任务**:写代码跑测试、管理文件、上网查资料、分析数据、调用 MCP 工具。
- **流式输出 + 可见思考** — 看着它推理,想完自动折叠,答案继续流式输出。
- **语音输入,安装即用** — 本地 STT 模型随安装包自带(约 20× 实时,纯 CPU)。
- **会话记忆** — 对话持久化、可搜索、可回放。
- **模型自动识别** — 自动列出 Ollama 里已拉的模型,上下文最高 256K。
- **可扩展** — 技能(markdown,用到才加载全文)+ MCP(`~/.ollama_agent/mcp.json`)。`AGENTS.md` 是写给 AI 看的接入教程。

## 快速开始

1. 安装 [Ollama](https://ollama.com) 并拉一个模型:
   ```
   ollama pull gemma4:e2b       # 快,4B 级
   ollama pull qwen3.5:2b       # 256K 长上下文
   ollama pull qwen3.5:35b-a3b  # MoE——低配机器上的"大模型"
   ```
2. 运行安装包(`蜂鸟-v1.0.0-中文安装包.exe`)→ 桌面快捷方式。
3. 打开,选模型,直接聊或派活。

## 按硬件选模型

| 机器 | 推荐模型 |
|------|---------|
| 入门(8GB 内存,纯 CPU) | `qwen3:0.6b` / `gemma3:1b` |
| 主流(核显笔记本) | `gemma4:e2b`(快)/ `qwen3.5:2b`(长上下文) |
| 高端(独显 32GB+) | `qwen3.5:35b-a3b`(MoE)/ `qwen3:32b` |

MoE 是"低配跑大模型"的关键;小模型最该吃**长上下文**——那是它的记忆。

## 安装技能与 MCP

- **技能**:往 `skills/`(exe 旁或 `~/.ollama_agent/skills/`)放一个带 frontmatter 的 markdown 文件。agent 只加载技能摘要,用到才读全文。
- **MCP**:在 `~/.ollama_agent/mcp.json` 加服务器配置——纯 JSON,格式见 `AGENTS.md`。

`AGENTS.md` 是写给 AI 看的接入文档,两者都有示例。

## 架构(简版)

```
AgentGUI(ttkbootstrap,中英双语)
   │  AGENT_STREAM=1
   ▼
ollama_agent.py — 主循环
   ├─ 分类:问答(聊天提示+只读工具,答完即停)
   │         vs 任务(完整 harness)
   ├─ 路由:任务 → 类别(文件/代码/网络/记忆/MCP)→ 只加载相关工具
   ├─ 执行:带 schema 校验的工具调用
   ├─ 验证:跑测试 → 解析真实失败(file:line)→ 反馈
   ├─ 守卫:安全门(拦 rm -rf/系统路径)、重复调用拦截
   └─ 持久化:会话 + 检查点,可续跑
```

## 路线图与说明

- 完整更新日志见 `RELEASE_NOTES.md`;设计文档在 `design/`。
- `bench/` 下是 39 轮基准:每个版本都是一次在三个目标模型上端到端跑的真任务。
- **诚实的边界**:2B 模型不会一次性重写你的代码库。它能稳定干 80% 的日常 agent 活(文件管理、查资料、写脚本、跑测试、整理),干不了时会响亮地失败——而不是悄悄做错。
