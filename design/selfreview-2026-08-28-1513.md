## P0 — 不修复则正式矩阵数据无效

     全部落在 `%TEMP%\lrab_goose\`(transcript 末行 `Wrote C:\...\Temp\lrab_goose\analysis.py` 实证)。
     按现 workdir 判分 = 冤枉 goose 得 0 分;而且 `lrab_goose` 是固定路径,每次 goose run 互相覆盖
     (跨 run 污染,正是 2631765 要消灭的东西)。另注意 transcript 里 goose 手工拼 PNG 字节伪造图——
     见第 5 条。

     临时 HOME 重定向),跑完后校验"产物路径 ⊆ run workdir",否则判 run 无效而非判 0 分;
     固定 temp 路径改为 per-run 唯一路径。

2. **opencode crash 被记为能力 0 分**
   - 发现: `m1_opencode_4b_WF06` wall=2.6s、exit=1、transcript 是 "Unexpected server error"——
     这是环境/启动失败,不是任务失败,但 score.json 记 total=0.0,与真实能力失败不可区分。
     roadmap §3.3 明确要求失败模式分类 {crash,...},score.json 里却没有 failure_mode 字段。
   - 怎么改: score.json 增加 `failure_mode` 字段(runner 依 exit code/wall/超时自动分类
     completed/partial/tool-format-failure/loop/fake-finish/timeout/crash);crash 格必须重跑,
     呈现表格时 crash 不进均分、单独披露。

3. **新 runner 末尾自拷贝必崩(残留死代码)**

     `copytree(workdir → 同一路径)`(src==dst),Windows 实测必崩(WinError 32/SameFileError)。
     score.json 在此之前已写所以数据不丢,但每个新 runner run 都以 traceback 收场,且
     "snapshot into archive" 语义已不存在。
   - 怎么改: 删除 run_bench.py:176-179 三行(workdir 本身就是归档)。

4. **"持久归档 eval_results/" 承诺与现场不符,数据边界半开半合**

     全部数据仍在 `bench/lrab/results/`,而这些目录不在 .gitignore 覆盖内(`!bench/lrab/` 放行了整棵树),
     一次 `git add -A` 就会把 8 个 run 的 transcript+workdir 提交进公开 repo。评测数据是 HN/JOSS
     生命线,当前无 canonical 归档、无 manifest,丢一块就说不清矩阵数据来源。
   - 怎么改: 定一个 canonical 位置并写死(建议就按 runner 默认 eval_results/),
     建 `results/MANIFEST.md`(run_id/agent/model/日期/失败模式/pre-fix 标记/是否 canonical);
     .gitignore 明确 eval_results/ 或 results/ 的边界(发布走 GitHub release,repo 只放汇总表)。

5. **判分器无法识破伪造产物;图表内容实际无人判**
   - 发现: `file_min_bytes` 只看字节数——goose transcript 已实证模型会为过关手拼 PNG 字节。
     反向同样成立: rubric WF-06 要求 judge 查"labeled axes/units",但 judge 只读文本
     (`_read` + trim 3000 字符),PNG 根本读不到——图的正确性目前 0 覆盖(smoke4 蜂鸟的图是真
     matplotlib 产物,签名/IEND 完好,但这靠自觉不靠判分)。
   - 怎么改: 图表类 artifact 加确定性校验(PNG 签名+IEND+PIL 可解码+最小分辨率),
     rubric judge 的输入改为"analysis.py 源码 + 图的文本侧写"或引入 vision judge;
     同时把 rubrics(15 个已生成、untracked)挂进 tasks/*.json 的 judge_rubric 字段形成闭环。

6. **judge==被测模型无硬防护**

     `--judge-model ornith-1.5:35b`,一旦某格 MUT=ornith-1.5:35b 且开了 judge,就是自我评分,无任何警告。
   - 怎么改: score_task/run_bench 加硬检查:judge_model 与 MUT model 同名即报错拒绝,
